# 회귀 방지 체크리스트

> **목적**: v1(`v1.4.1`)에서 **이미 고친 버그를 v2에서 다시 만들지 않기 위한** 목록.
> 재작성의 가장 큰 위험은 새 버그가 아니라 **잊힌 옛 버그**다.
>
> **사용법**: 각 항목을 구현 중 테스트로 전환하고 체크박스를 채운다.
> `스택 무관` 표시는 프레임워크를 바꿔도 그대로 유효하다는 뜻이다.
>
> **출처**: `591568d`, `eecb12e`, `1af6412`, `44ad824`, `4dfa25f`, `0ea48be` 커밋 및 v1 코드 분석.

## A. 게임 로직

### A1. 정답 비교 정규화 · `스택 무관`
- [x] 라이어의 정답을 비교할 때 **소문자화 + 모든 공백 제거 + 유니코드 NFC 정규화**를 거친다.
- **왜**: 한글은 조합형/완성형 표현이 달라도 같은 글자로 보인다.
  IME에 따라 다른 코드포인트가 입력되어 정답이 오답 처리된다.
- **테스트**: `"김치찌개"` vs `" 김치 찌개 "`, NFD로 조합된 동일 문자열, 영문 대소문자 혼용.

### A2. 빈 집계에 최댓값 연산 · `스택 무관`
- [x] 아무도 지목하지 않은 상태에서 최다 득표를 계산해도 안전하다.
- **왜**: 빈 배열에 `Math.max(...[])`는 `-Infinity`를 반환해 조용히 잘못된 분기를 탄다.
- **테스트**: 지목 0건으로 토론 종료 → 설명 단계 복귀(1회차) / 라이어 승(2회차).

### A3. 순서 인덱스 범위 · `스택 무관`
- [ ] 현재 설명자 인덱스가 순서 배열 범위를 벗어나면 명시적으로 처리한다.
- **왜**: 설명 도중 플레이어가 이탈하면 인덱스와 배열 길이가 어긋난다.
- **테스트**: 3번째 설명자 차례에 2번째 플레이어가 이탈 → 진행이 깨지지 않는다.

### A4. 무작위 셔플 알고리즘 · `스택 무관`
- [x] 단어 선정과 발언 순서 셔플에 **Fisher-Yates**를 사용한다.
- **왜**: `sort(() => Math.random() - 0.5)`는 균등하지 않다.
  라이어 게임에서 순서/단어 편향은 곧 밸런스 붕괴다.
- **테스트**: 다회 시행 시 각 위치의 분포가 균등한지 통계 검증.

### A5. 라이어 선정 독립성 · `스택 무관` · **v2 신규**
- [x] 라운드마다 라이어를 **완전 독립 균등 무작위**로 뽑는다.
      직전 라이어 제외 같은 로테이션을 넣지 않는다.
- **왜**: 제외 규칙은 "확정 시민"을 만들어 정보를 유출한다 (REQUIREMENTS D10).
- **테스트**: N라운드 시행 후 각 플레이어의 라이어 선정 횟수가 이항분포를 따르고,
  직전 라이어가 연속 선정되는 경우가 실제로 발생한다.

### A6. 과반 판정에서 무효표 제외 · `스택 무관`
- [x] 최종 투표는 `찬성 > (찬성 + 반대) / 2`로 판정한다. 미투표는 분모에서 제외한다.
- **왜**: 전체 인원을 분모로 삼으면 기권이 사실상 반대표가 된다.
- **테스트**: 6인·피고 제외 5명 중 2명만 투표(찬2 반0) → 확정.

## B. 자원 · 생명주기

### B1. 방 삭제 시 걸린 타이머 전부 취소 · `스택 무관`
- [ ] 방이 사라질 때 그 방에 예약된 **모든** 지연 콜백을 취소한다.
- **왜**: 유령 콜백이 이미 없는 방을 참조해 크래시하거나 메모리를 붙잡는다.
  v1은 이것 때문에 `pendingCallbacks` 맵을 별도로 관리해야 했다.
- **테스트**: 연출 지연 중 전원 퇴장 → 방 삭제 → 콜백이 실행되지 않는다.
- **v2 메모**: 타이머가 방 생명주기에 자동으로 묶이는 구조를 택하면 이 문제가 구조적으로 사라진다.

### B2. 중복 삭제 타이머 방지 · `스택 무관`
- [ ] 빈 방 삭제 예약이 중복으로 걸리지 않는다. 재입장 시 예약이 취소된다.
- **테스트**: 퇴장 → 재입장 → 다시 퇴장 → 삭제가 정확히 1회만 예약된다.

### B3. 클라이언트 자원 정리 · 프론트
- [ ] 페이지 이탈·컴포넌트 해제 시 소켓 연결, 모든 인터벌/타임아웃을 정리한다.
- **왜**: v1은 로비·방 생성 페이지에서 소켓이 정리되지 않아 연결이 누적됐다.
- **테스트**: 페이지 전환을 반복해도 서버의 연결 수가 증가하지 않는다.

### B4. 서버 우아한 종료 · `스택 무관`
- [x] `SIGTERM`/`SIGINT`에서 소켓 서버와 HTTP 서버를 순서대로 닫는다.
- **v2 메모**: 진행 중 게임은 영속화하지 않기로 했으므로(D9),
  종료 전 접속자에게 안내 메시지를 보내는 것까지만 한다.

## C. 보안 · 입력

### C1. 비밀 정보를 URL에 노출 금지 · `스택 무관`
- [ ] 방 비밀번호와 호스트 권한 토큰을 **URL 쿼리스트링에 절대 싣지 않는다.**
- **왜**: 브라우저 히스토리, 리퍼러 헤더, 서버 액세스 로그에 그대로 남는다.
- **테스트**: 방 생성/참가 전 과정에서 `window.location`에 비밀 값이 나타나지 않는다.

### C2. 정보 은닉 — 페이로드 수준 · `스택 무관` · **v2에서 3계층으로 확대**
- [x] 라운드 진행 중, 각 뷰어에게 전송되는 데이터에
      **타인의 제시어와 라이어의 정체가 존재하지 않는다.**
- [x] 관전자 투영에 **제시어가 없다.**
- [x] 바보 모드에서 라이어 본인의 투영에 **자신이 라이어라는 정보가 없다.**
- **왜**: 개발자 도구 한 번으로 게임이 무의미해진다. 제품의 존재 이유다.
- **테스트**: 각 뷰어 유형의 투영 결과를 직렬화하여 금칙어(라이어 ID, 상대 단어)
  포함 여부를 단위 테스트로 강제한다. **이 테스트는 반드시 있어야 한다.**

### C3. XSS — 계층 분리 · `스택 무관` · **v1 버그 수정 필요**
- [x] **검증은 저장 시, 이스케이프는 렌더 시**에 한다.
- **v1의 실제 버그**: 저장 시점에 HTML 엔티티로 인코딩한 뒤 `x-text`로 렌더해
  **이중 이스케이프**가 발생했다. 닉네임 `A&B`가 화면에 `A&amp;B`로 표시된다.
  덤으로 닉네임 중복 검사가 인코딩된 값 기준이라 `A<B`와 `A&lt;B`가 다른 사람 취급됐다.
- **테스트**: 닉네임 `A&B`, 채팅 `<script>`, 방 이름 `"따옴표"`가
  화면에 **입력 그대로** 보이고 스크립트는 실행되지 않는다.

### C4. CORS 환경별 분리 · `스택 무관`
- [ ] 프로덕션에서는 `ALLOWED_ORIGINS`로 출처를 제한하고, 개발에서는 열어둔다.
- **테스트**: `NODE_ENV=production`에서 허용되지 않은 출처의 소켓 연결이 거부된다.

### C5. 서버 측 입력 검증 · `스택 무관` · **v1 미비**
- [x] 클라이언트가 보내는 모든 메시지를 **런타임에 검증**한다.
- **v1의 문제**: 타입 선언만 있고 런타임 검증이 없어 `targetId` 누락, 타입 불일치,
  범위 밖 값이 그대로 로직에 들어갔다.
- **테스트**: 필수 필드 누락, 잘못된 타입, 범위 초과 값을 보내도 서버가 죽지 않고 거부한다.

### C6. 권한 검증 · `스택 무관`
- [x] 호스트 전용 동작(설정 변경, 강퇴, 매치 시작, 유예 건너뛰기)은 서버에서 검증한다.
- [x] 피고 전용 동작(변론 종료), 라이어 전용 동작(정답 제출)도 마찬가지다.
- [x] 자기 자신 지목·자기 자신 강퇴가 차단된다.
- **테스트**: 비호스트가 호스트 전용 메시지를 보내면 거부된다.

### C7. 레이트 리밋 · `스택 무관`
- [ ] 피드백 제출에 IP당 쿨다운(60초)이 있고, 쿨다운 기록이 주기적으로 정리된다.
- **v2 메모**: 채팅 스팸 제한은 v1에 없었다. 필요 여부를 판단할 것.

## D. 프론트엔드

### D1. 연속 입력 이벤트 · 프론트
- [x] 슬라이더 등 연속 입력은 `change`(확정 시점)로 처리한다. `input`(변경 중)이 아니다.
- **왜**: 드래그 중 매 픽셀마다 서버 메시지가 발사된다.
- **테스트**: 최대 인원 슬라이더를 4→10으로 드래그해도 메시지가 1건만 나간다.

### D2. 리스트 렌더링 키 충돌 · 프론트
- [ ] 채팅·플레이어 목록 등 반복 렌더링의 키가 **고유**하다.
- **왜**: 타임스탬프만으로 키를 만들면 같은 밀리초 메시지끼리 충돌한다.
- **테스트**: 동시에 도착한 메시지 2건이 모두 렌더링된다.

### D3. 스크립트 로드 순서 · 프론트
- [ ] 의존 관계가 있는 스크립트의 로드 순서가 보장된다.
- **v1의 문제**: `defer` 스크립트들의 순서 의존성 때문에 초기화가 간헐적으로 실패했다.
- **v2 메모**: **번들링하면 이 문제 자체가 사라진다.**

### D4. 존재하지 않는 속성 참조 · 프론트
- [ ] 서버가 보내지 않는 필드를 UI가 참조하지 않는다.
- **v1의 버그**: 플레이어 목록에서 `isConnected`를 참조했으나 서버가 보내지 않았다.
- **v2 메모**: 프로토콜 타입을 서버·클라이언트가 **공유**하면 컴파일 타임에 잡힌다.
  **v2에서는 `isConnected`가 실제로 필요하다** (재접속 유예 표시).

### D5. 외부 의존성 버전 고정 · 인프라
- [ ] 모든 외부 라이브러리 버전을 고정한다. CDN이면 특히.
- **v2 메모**: 번들에 포함하면 CDN 의존 자체가 사라진다.

### D6. 클라이언트 시계 신뢰 금지 · `스택 무관` · **v1 설계 결함**
- [x] 남은 시간 계산이 **클라이언트 시계 오차에 영향받지 않는다.**
- **v1의 문제**: 서버가 절대 시각(`endTime`)을 보내고 클라이언트가 자기 `Date.now()`와
  비교했다. 시계가 어긋난 사용자는 실제와 다른 시간을 봤다.
- **해법**: 상대 시간(`remainingMs`)을 보내고 수신 시점 기준으로 카운트다운한다.
- **테스트**: 클라이언트 시계를 ±5분 틀어도 표시되는 잔여 시간이 정확하다.

## E. CI · 빌드

### E1. Node 버전 일치 · 인프라
- [x] CI, Dockerfile, 로컬 개발의 Node 메이저 버전이 일치한다.
- **v1의 문제**: lockfile 호환성 때문에 CI가 깨졌다.

### E2. 테스트 파일 빌드 제외 · 인프라
- [x] 프로덕션 빌드 산출물에 테스트 파일이 포함되지 않는다.

### E3. 배포 트리거 · 인프라
- [x] 이미지 배포는 **`v*` 태그 푸시에만** 트리거된다.
      브랜치 푸시나 main 병합으로 프로덕션이 바뀌지 않는다.
- **왜**: v2 재작성 기간 동안 v1 서비스를 안전하게 유지하는 근거다.

## F. v2 신규 — 반드시 테스트해야 할 것

v1에 없던 기능이라 과거 버그는 없지만, **구조적으로 위험한 지점**이다.

### F1. 재접속 왕복
- [x] 각 단계(제시어 확인 / 설명 / 토론 / 변론 / 투표 / 정답)에서 끊고 재접속했을 때
      자리·역할·제시어·점수가 정확히 복구된다.
- [x] 유예 만료 직전(29초)과 직후(31초) 재접속의 결과가 명확히 다르다.
- [x] 재접속 후 받은 상태만으로 화면이 완전히 복구된다 (누락된 델타가 없다).

### F2. 일시정지 정합성
- [x] 유예 중 타이머가 실제로 멈추고, 재개 시 남은 시간이 보존된다.
- [x] 유예 중에도 채팅은 동작한다.
- [x] 호스트의 "기다리지 않고 계속"이 즉시 유예를 끝낸다.
- [ ] **호스트 본인이 끊긴 경우** 30초 후 자동 진행 + 호스트 이양이 일어난다.
- [x] 동시에 2명 이상 끊긴 경우가 올바르게 처리된다.

### F3. 관전자 불변식
- [x] `플레이어 수 + 관전자 수 ≤ 최대 인원`이 **항상** 성립한다.
- [x] 다음 라운드 시작 시 전원 승격해도 정원을 넘지 않는다.
- [x] 관전자 투영에 제시어·라이어 정체가 없다 (C2와 중복 확인).
- [x] 관전자가 채팅을 보낼 수 없다 (서버에서 거부).
- [x] 플레이어 이탈로 정원에 여유가 생기면 관전 슬롯이 열린다.

### F4. 기회 상한
- [x] 설명 2회, 토론 2회를 넘지 않는다.
- [x] 2회차 토론에서 "설명 다시하기" 선택지가 제시되지 않는다.
- [x] 상한 소진 후 무투표 / 동점 / 투표 미달이 **모두 라이어 승**으로 귀결된다.
- [x] 어떤 입력 시퀀스로도 라운드가 무한히 지속되지 않는다.

### F5. 점수 정합성
- [x] 각 결과 유형별 점수 배분이 규칙과 일치한다.

## G. Colyseus 특유의 함정

> 출처: `docs/spikes/colyseus/FINDINGS.md` (2026-08-18 스파이크에서 **실제로 겪은** 것들).
> 고정 버전: `colyseus@0.17.10` + `@colyseus/sdk@0.17.43`.

### G1. `onLeave`의 두 번째 인자는 boolean이 아니라 close code · **최우선**
- [ ] `onLeave(client, code: number)`에서 `const consented = code === 4000;`으로 판정한다.
- **왜**: 0.16의 `consented: boolean`이 0.17에서 `code: number`로 바뀌었다.
  `if (consented)`로 쓴 코드는 **타입 에러 없이 컴파일되지만 동작이 정반대**다 —
  숫자는 항상 truthy라 모든 끊김이 정상 퇴장으로 처리되어 **재접속이 영원히 안 된다.**
- **테스트**: 비정상 종료(4000이 아닌 코드) 후 유예 내 재접속이 성공한다.

### G2. `StateView`는 `@colyseus/schema`에서 import
- [x] `import { StateView } from "@colyseus/schema"` — `colyseus`에서 가져오지 않는다.
- **왜**: `colyseus`에서 import하면 `undefined`이고 런타임에야 터진다.

### G3. `Server.listen()`을 반드시 사용
- [x] 외부 http 서버를 직접 `listen()` 하지 않고 `gameServer.listen(PORT)`를 쓴다.
- **왜**: `setTransport()`가 `Server.listen()` 안에서 실행된다. 건너뛰면 매치메이킹이
  `Cannot read properties of undefined (reading 'protocol')`로 죽는다.

### G4. 버전 정확 고정
- [x] `colyseus`와 `@colyseus/sdk` 버전을 캐럿/틸드 없이 정확히 고정한다.
- **왜**: `@colyseus/core@0.16.25`는 `workspace:^` 미해결 상태로 배포되어 **설치 자체가 불가능**했다.
  SDK의 `next` 태그는 이미 0.18이다. 버전 이동이 빠르고 QA가 균일하지 않다.
- **테스트**: `npm ci`가 깨끗한 환경에서 성공한다 (CI에서 이미 검증됨).

### G5. 클라이언트 SDK 패키지명
- [x] `colyseus.js`가 아니라 **`@colyseus/sdk`** 를 쓴다.
- **왜**: 0.17에서 개명됐다. 구 `colyseus.js@0.16.x`는 0.17 서버와 **wire 비호환**이다
  (seat reservation 응답이 중첩 구조 → 평면 구조로 변경).

### G6. 테스트 작성 시 방 최소 가동시간
- [ ] 재접속 테스트는 방 생성 후 **5초 이상** 지난 뒤 수행한다.
- **왜**: 0.17에 `min uptime: 5000ms` 가드가 있어 그 전에는 자동 재접속이 거부된다.
  프로덕션에서는 무관하지만 **테스트가 거짓 실패**한다.

### G7. 정보 은닉 테스트를 바이트 수준으로
- [x] C2 테스트를 **디코딩된 state가 아니라 전송 바이트**에서 검증한다.
- **왜**: 디코딩 결과만 보면 인코더 변경이나 StateView 설정 실수를 놓칠 수 있다.
  스파이크의 `run.ts` C2-5가 참조 구현이다 (소켓 `send`를 래핑해 바이트를 수집하고
  센티널 문자열을 검색).
- **이 테스트가 깨지면 배포를 막는다.**

### G8. `Delayed.pause()`는 중첩 카운트를 하지 않는다 · **v2 신규**
- [x] 일시정지는 **끊긴 인원 수를 직접 세어** 0이 될 때만 `resume()` 한다.
- **왜**: `pause()`를 두 번 호출해도 `resume()` 한 번이면 타이머가 재개된다.
  2명이 끊겼다가 1명만 복귀했는데 게임이 진행되어 버린다.
- **테스트**: 2명 동시 끊김 → 1명만 복귀 → 타이머가 여전히 정지 상태다.
  두 번째도 복귀해야 재개된다.

### G9. `toJSON()` 스냅샷도 StateView를 존중하는지 확인
- [x] 클라이언트 어댑터가 쓰는 `state.toJSON()` 결과에 타인의 비밀 필드 **키가 없다.**
- **왜**: 어댑터가 전체 스냅샷을 만들므로, 여기서 새면 UI 전체로 샌다.
- **테스트**: 관전자 스냅샷을 직렬화해 금칙어를 검색한다 (C2/G7와 함께).

### G10. `Room` 제네릭이 0.17에서 바뀌었다 + `tsc --noEmit`을 CI에 둘 것
- [x] `class LiarRoom extends Room<{ state: RoomSchema }>` 형태를 쓴다 (0.16의 `Room<State>` 아님).
- [x] **CI에 `tsc --noEmit`이 있다.**
- **왜**: 0.17에서 `Room<T extends RoomOptions>`로 바뀌어 `T`가 `{ state, metadata?, client? }` 형태다.
  더 중요한 건 **발견 경위**다 — 스파이크를 `tsx`로 실행했더니 타입 체크를 건너뛰어
  이 오류가 끝까지 보이지 않았다. `tsc`를 처음 돌린 순간 드러났다.
  `tsx`/`vite`는 트랜스파일만 하고 타입을 검사하지 않는다.
- **테스트**: CI가 `tsc -p tsconfig.server.json --noEmit`과 `svelte-check`를 모두 실행한다.

### G11. Vite HMR과 Colyseus WebSocket이 같은 포트를 공유하면 안 된다 · **v2 신규**
- [x] 개발 서버에서 HMR이 **별도 포트**를 쓴다 (`vite.config.ts`의 `server.hmr.port`).
- **왜**: Colyseus의 방 소켓 경로가 `/{processId}/{roomId}` 라 접두사로 가를 수 없어
  프록시가 모든 WebSocket 업그레이드를 Colyseus로 넘긴다. HMR이 같은 포트를 쓰면
  `ws://<vite>/?token=...` 이 Colyseus로 흘러들어가
  `Invalid WebSocket frame: invalid status code ...` 가 쏟아진다.
  **증상이 게임 로직과 무관해 보여 원인을 찾기 어렵다.**
- **테스트**: `npm run dev` 후 브라우저로 게임에 접속했을 때 서버 로그에
  `Invalid WebSocket frame` 이 한 건도 없다.

### G12. Svelte 룬은 `.svelte` / `.svelte.ts` 에서만 쓴다 · **v2 신규**
- [x] 룬(`$state`·`$derived`·`$effect`·`$props`)을 쓰는 파일은 `.svelte` 또는 `.svelte.ts` 다.
- **왜**: 평범한 `.ts` 에 쓰면 **`tsc`·`svelte-check`·`vite build`가 모두 통과하는데**
  브라우저가 모듈을 로드하는 순간 `Uncaught Svelte error: rune_outside_svelte` 로 죽는다.
  정적 검사가 하나도 잡아주지 않는다.
- **테스트**: `client/conventions.test.ts` 가 파일명 규약을 강제한다.
- **함께 볼 것**: 파일명을 바꾸면 import 경로도 `*.svelte.js` 로 바꿔야 한다.

## H. 클라이언트 검증 (M6에서 도입)

정적 검사(`tsc`·`svelte-check`·`vite build`)가 전부 통과하는데 브라우저에서만
죽는 부류가 실제로 나왔다 (G12). 두 계층으로 막는다.

### H1. 1계층 — happy-dom 스모크 · 로컬·CI
- [x] 모든 페이즈 화면이 실제로 마운트된다 (`client/smoke.test.ts`).
- [x] **화면에 새면 안 될 정보가 렌더되지 않는다** — 개표 미달 시 라이어 여부,
      관전자 화면의 제시어 자리.
- [x] 역할별 UI 게이팅 (호스트/피고/관전자).
- **왜 렌더 수준에서도 보는가**: 서버가 데이터를 안 보내도 클라이언트가
  다른 경로로 추론해 표시하면 똑같이 샌다.

### H2. 1.5계층 — 실 Colyseus 서버 통합 · 로컬·CI
- [x] 실제 WebSocket 위에서 연결 계층(`connection.svelte.ts`)이 동작한다.
- [x] **다른 참가자가 들어오면 화면이 스스로 갱신된다** —
      Colyseus 패치 → `toJSON()` → Svelte `$state` → DOM 까지 이어지는지.
- [x] 서버가 거부하면 오류가 상태에 담긴다.
- **왜 브라우저가 필요 없나**: Node 22에 전역 `WebSocket`이 있어 SDK가 그대로 붙는다.
      3.6초에 끝난다.

### H3. E2E (Playwright) — **수동 전용, 자동화에서 제외**
- [ ] CSS로 요소가 안 보이거나 클릭이 막히지 않는다. ← Playwright만 잡는 영역
- **자동화에서 뺀 이유**: H1·H2가 실제 위험을 덮는다. Playwright의 marginal한
      이득보다 브라우저 설치 ~170MB와 실행 1~2분이 비싸다.
      UI를 크게 손봤을 때 손으로 돌린다.
- **미검증**: 아직 실제 브라우저에서 돌려본 적이 없다 (WSL에 `libnss3` 없음).
