## 0. 제품 정의

> 4~10명이 **로그인 없이** 링크 하나로 모여, 한 명의 라이어를 찾아내는
> **텍스트 기반** 실시간 추리 게임. 여러 라운드를 치러 누적 점수로 승자를 가린다.

세 가지 제약이 나머지 전부를 규정한다.

| 제약 | 파생되는 것 |
|---|---|
| **계정 없음** | 닉네임 기반 정체성, 호스트 권한 이양, 세션 기반 재접속 |
| **텍스트만 (음성 없음)** | 한줄 설명 단계, 채팅, 모든 단계의 제한시간 |
| **가벼운 운영** | DB 없음, 단일 컨테이너, 인메모리 상태, 재시작 시 진행 중 게임 소실 감수 |

## 1. 도메인 규칙

구현과 무관하게 참인 게임 규칙. 이 절이 곧 게임이다.

### 1.1 인원과 역할

- 한 라운드의 플레이어는 **4명 이상 10명 이하**.
- 매 라운드 정확히 **1명**이 라이어, 나머지 전원이 시민.
- 시민은 **전원 같은 단어**를 받는다.
- **라이어 선정은 매 라운드 완전 독립 시행**(균등 무작위)이다.
  직전 라운드 라이어를 제외하는 등의 로테이션을 **넣지 않는다** — 제외 규칙은
  "확정 시민"을 만들어 정보를 유출한다.

### 1.2 게임 모드

|  | 시민 | 라이어 (일반 모드) | 라이어 (바보 모드) |
|---|---|---|---|
| 받는 제시어 | 정답 단어 | **없음** | **다른 단어** |
| 자기 정체 인지 | 시민임을 앎 | 라이어임을 **앎** | 라이어임을 **모름** |

- 카테고리는 라운드 시작 시 **전원에게 공개**된다.
- 바보 모드의 두 단어는 **같은 카테고리 내에서 완전 무작위**로 뽑는다.
  의미적 유사성을 보장하지 않는다 (의도된 결정 — §8 D6).

### 1.3 라운드 진행

```
제시어 확인
    │
    ▼
한줄 설명 ◄──────────────────────┐
    │                            │ (기회 남음)
    ▼                            │
토론 + 지목 ─────────────────────┤
    │                            │
    ├─ 무투표 ────────────────────┤
    ├─ "설명 다시하기" 최다 ───────┘
    │
    ├─ 동점 ──────────────────► 재토론 (기회 남으면)
    │
    └─ 단독 최다 득표
            │
            ▼
        최후 변론
            │
            ▼
        최종 투표
            │
            ├─ 과반 미달 ────────► 재토론 (기회 남으면)
            │
            └─ 과반 찬성 → 처형
                    │
                    ├─ 처형자 == 시민 ──► 라이어 승 · 라운드 종료
                    │
                    └─ 처형자 == 라이어 ──► 정답 맞추기 ──► 라운드 종료
```

기회를 모두 소진하고도 결론이 나지 않으면 **라이어 승**으로 라운드가 끝난다(§1.5).

### 1.4 단계별 규칙

#### ① 제시어 확인
- 각자 자기 단어를 확인한다. 시간 제한 **없음**.
- **전원이 확인해야** 다음 단계로 넘어간다.

#### ② 한줄 설명
- 발언 순서는 **무작위**로 정해지고 전원에게 공개된다.
- 순서대로 한 명씩, 자기 단어를 한 줄로 설명한다 (최대 100자).
- 각 차례에 제한시간이 있고, **미제출 시 빈 설명(`...`)이 자동 제출**된다.
- 전원이 제출하면 토론으로 넘어간다.
- 제출된 설명은 라운드 내내 전원에게 보인다.

#### ③ 토론 + 지목
- 자유 채팅과 지목이 **동시에** 진행된다.
- 각자 **1표**를 행사하며, **지목은 언제든 변경 가능**하다.
- **자기 자신은 지목할 수 없다.**
- 사람 대신 **"한줄 설명 다시하기"** 를 지목할 수 있다.
  (단, 설명 기회가 남아 있을 때만 선택지로 제시된다 — §1.5)
- 현재 지목 현황(누가 몇 표)은 **실시간으로 전원에게 공개**된다.
- **전원이 지목을 마치면** 남은 시간과 무관하게 최대 5초 뒤 단계가 종료된다.

#### ④ 지목 집계 — 우선순위 순으로 판정

| 조건 | 결과 |
|---|---|
| 아무도 지목하지 않음 | 한줄 설명부터 다시 (순서 재추첨, 설명 초기화) |
| "설명 다시하기"가 최다 | 한줄 설명부터 다시 (동일) |
| 최다 득표 동점 | 재토론 (지목만 초기화, 설명은 유지) |
| 단독 최다 득표 | 그 사람이 **피고**가 되어 최후 변론 |

#### ⑤ 최후 변론
- **피고만** 채팅으로 발언할 수 있다. 다른 참가자는 읽기만 한다.
- 피고가 스스로 종료하거나, 제한시간이 다하면 종료된다.

#### ⑥ 최종 투표
- **피고를 제외한** 전 플레이어가 찬성/반대를 던진다.
- **미투표는 무효표**이며, 과반 계산의 **분모에서 제외**된다.
- 판정: `찬성 > (찬성 + 반대) / 2` → **처형 확정**. 미달이면 재토론.
- 투표 도중에는 **투표한 인원 수만** 공개되고, 찬반 내역은 개표 시점에 공개된다.

#### ⑦ 정답 맞추기
- 처형자가 **라이어였을 때만** 진행된다.
- 라이어가 제한시간 내에 **시민의 제시어**를 입력한다.
- 판정: **소문자화 + 모든 공백 제거 + 유니코드 NFC 정규화** 후 완전 일치.
- 미제출은 오답으로 처리한다.

### 1.5 기회 상한 — 라운드 종료 보장

> **원칙: 시민에게 주어진 기회는 유한하다. 소진하고도 라이어를 처형하지 못하면 라이어 승.**

라운드마다 카운터 두 개를 둔다.

| 카운터 | 상한 | 증가 시점 |
|---|---|---|
| 설명 단계 진입 횟수 | **2회** | 무투표 또는 "다시하기" 가결로 되돌아갈 때 |
| 토론 단계 진입 횟수 | **2회** | 동점 또는 최종 투표 과반 미달로 되돌아갈 때 |

상한 소진 후의 동작:

| 상황 | 1회차 | 2회차 (소진) |
|---|---|---|
| 아무도 지목 안 함 | 설명부터 다시 | **라이어 승 · 라운드 종료** |
| "다시하기" 최다 | 설명부터 다시 | 선택지 자체를 **제시하지 않음** |
| 지목 동점 | 재토론 | **라이어 승 · 라운드 종료** |
| 최종 투표 과반 미달 | 재토론 | **라이어 승 · 라운드 종료** |

이로써 라운드의 **최대 소요 시간이 상한을 가진다**(10인·최대 설정 기준 약 15분).

### 1.6 승패 판정

| 조건 | 승자 |
|---|---|
| 라이어를 처형하지 못함 (시민이 처형되거나, 기회 소진) | **라이어** |
| 라이어를 처형했고, 라이어가 제시어를 맞추지 못함 | **시민** |
| 라이어를 처형했고, 라이어가 제시어를 맞춤 | **라이어** (역전승) |

**라운드 종료 시 전원에게 공개**: 승자, 라이어의 정체, 시민 제시어,
라이어 제시어(바보 모드), 라이어가 추측한 답, 이번 라운드 점수 변동.

### 1.7 매치와 점수

#### 매치 구조

```
대기실 → [ 라운드 → 점수판 ] × N → 최종 순위 → 대기실
```

- 호스트가 대기실에서 **라운드 수**를 정한다: **3 / 5 / 무제한** (기본 **3**).
- 라운드 사이 **점수판** 화면에서 호스트가 다음 라운드를 시작한다.
  자동 진행하지 않는다 — 쉬는 시간이 필요하다.
- 무제한이면 호스트가 매치를 끝낼 때까지 계속된다.

#### 점수 규칙

| 결과 | 점수 |
|---|---|
| **라이어 승** (미검거 또는 검거 후 정답) | 라이어 **+2** |
| **시민 승** (검거 후 오답) | 시민 전원 **+1** |
| **정확 지목 보너스** | 라이어를 지목한 시민 **+1** (승패 무관) |
| **무효 라운드** | 전원 0 |

- 정확 지목 보너스는 그 라운드에서 **마지막으로 실시된 지목**을 기준으로 한다.
- 라이어가 +2인 근거: 각자 라이어가 되는 횟수는 확률적으로 같으므로,
  공정 조건은 `라이어 점수 = 시민 점수 × (1−p)/p` (p = 라이어 승률).
  텍스트 기반 라이어 게임은 라이어가 다소 불리하다.
  **이 값들은 상수로 분리하여 플레이 후 조정 가능해야 한다.**

#### 점수와 참가자 변동

- 매치 도중 합류한 사람(관전 → 플레이어 승격)은 **0점**부터 시작한다.
- 이탈이 확정된 사람은 점수판에서 제거된다.
- **재접속 유예(30초) 내에 돌아오면 점수가 복원**된다.
- **무효 라운드는 라운드 수에 포함하지 않는다** (다시 진행한다).

## 2. 정보 공개 범위

> 라이어 게임에서 정보 은닉은 기능이 아니라 **제품 그 자체**다.
> 뷰어 종류가 셋이므로, 상태를 뷰어별로 투영하는 단일 지점을 반드시 둔다.

| 정보 | 플레이어 (본인) | 플레이어 (타인) | **관전자** |
|---|:---:|:---:|:---:|
| 내 제시어 | ✅ | — | — |
| **타인의 제시어** | ❌ | ❌ | ❌ |
| 내가 라이어인지 (일반 모드) | ✅ | ❌ | ❌ |
| 내가 라이어인지 (바보 모드) | ❌ | ❌ | ❌ |
| **라이어의 정체** (라운드 진행 중) | ❌ | ❌ | ❌ |
| 카테고리 | ✅ | ✅ | ✅ |
| 한줄 설명 / 채팅 / 지목 현황 | ✅ | ✅ | ✅ |
| 최종 투표 찬반 내역 (개표 전) | 본인 표만 | ❌ | ❌ |
| 최종 투표 인원 수 (개표 전) | ✅ | ✅ | ✅ |
| **라운드 결과 공개 후 전체** | ✅ | ✅ | ✅ |

**절대 요구사항**: 라이어의 정체와 타인의 제시어는 라운드 진행 중
**해당 뷰어에게 전송되는 데이터에 존재해서도 안 된다.**
개발자 도구로 게임을 깰 수 있으면 제품이 무의미하다.

## 3. 기능 요구사항

### F1. 정체성 (계정 없음)
- 사용자는 **닉네임만**으로 참여한다 (2~10자).
- 닉네임은 브라우저에 기억되어 다음 방문 시 재사용된다.
- 최초 방문자에게 **랜덤 한글 닉네임**(형용사+동물)을 자동 제안한다.
- 로비에서 닉네임을 직접 수정하거나 다시 뽑을 수 있다.
- **한 방 안에서 닉네임은 유일**해야 한다.

### F2. 로비
- 방 목록이 **실시간으로 갱신**된다 (생성·인원 변동·상태 변경이 즉시 반영).
- 노출 조건과 표시:

  | 방 상태 | 노출 | 표시 |
  |---|---|---|
  | 대기 중 · 정원 미달 | ✅ | `참가` 버튼 |
  | **게임 중 · 정원 여유 있음** | ✅ | **`관전 가능` 배지 + `관전하기` 버튼** |
  | 게임 중 · 정원 꽉 참 | ❌ | — |
  | 인원 0명 | ❌ | — |

- 정렬은 **참가 가능한 방 우선**.
- 각 방에 대해: 이름, 공개 여부, 현재/최대 인원, 게임 모드, 카테고리, 상태.
- 비공개 방도 **목록에 보이되** 자물쇠로 표시되고 참가 시 비밀번호를 요구한다.
- 참가 실패 사유(정원 초과, 비밀번호 오류, 닉네임 중복)를
  **방에 들어가기 전에** 알려준다.
- 게임 규칙 설명이 로비에 있다.

### F3. 방 생성과 설정
- 생성 시 정하는 것: 방 이름(1~20자), 공개/비공개, 비공개면 비밀번호(1~20자).
- 만든 사람이 **호스트**가 된다.
- **게임 설정은 대기실에서** 호스트가 변경하며, 변경은 전원에게 즉시 반영된다.

  | 설정 | 선택지 | 기본값 |
  |---|---|---|
  | 게임 모드 | 일반 / 바보 | 일반 |
  | 카테고리 | 랜덤 + 6종 | 랜덤 |
  | 최대 인원 | 4~10 | 10 |
  | **라운드 수** | 3 / 5 / 무제한 | **3** |
  | 설명 시간 | 15 / 30 / 60초 | 30초 |
  | 토론 시간 | 1 / 2 / 3분 | 2분 |
  | 변론 시간 | 15 / 30 / 60초 | 15초 |

- 최대 인원은 **현재 인원보다 작게** 설정할 수 없다.
- 카테고리 "랜덤"은 **매 라운드 시작 시** 실제 카테고리로 확정되어 공개된다.
- 최종 투표 시간(15초)과 정답 맞추기 시간(15초)은 **설정 불가**.

### F4. 대기실
- 참가자 목록이 실시간으로 보인다 (호스트 표시 포함).
- 호스트는 참가자를 **강퇴**할 수 있다 (대기실에서만, 자기 자신 제외).
- 호스트는 **4명 이상**일 때 매치를 시작할 수 있다.
- 호스트가 나가면 **다음 참가자에게 자동 이양**된다.

### F5. 게임 진행 표시
- 제한시간이 있는 모든 단계에서 **남은 시간이 전원에게 표시**된다.
- 지금 무엇을 해야 하는지, 내 차례인지가 명확해야 한다.
- 진행 상황(확인 완료 인원, 지목 현황, 투표 인원)이 실시간 공개된다 — §2의 범위 내에서.

### F6. 소통
- 방 안 자유 채팅. 시스템 메시지(입장/퇴장/단계 전환)도 같은 흐름에 표시된다.
- **최후 변론 중에는 피고만** 발언할 수 있다.
- **관전자는 읽기 전용**이다 (§F7).
- 채팅은 최근 **100개**만 유지된다.
- 모바일에서는 채팅이 별도 시트로 열리며,
  **읽지 않은 개수 배지**와 **새 메시지 미리보기 토스트**를 제공한다.

### F7. 관전

- **관전자 정원 = 최대 인원 − 현재 플레이어 수.**
  즉 `플레이어 + 관전자 ≤ 최대 인원`이 항상 유지된다.
  이 불변식 덕분에 **다음 라운드 자동 승격이 절대 정원을 넘지 않는다.**
- 매치가 진행 중일 때 방에 들어오면 자동으로 관전자가 된다.
  (대기실 상태에서는 관전자가 존재하지 않는다 — 들어오면 곧바로 플레이어)
- 관전자가 보는 정보는 **§2의 관전자 열**과 같다. **제시어도 보이지 않는다.**
  관전자는 신 시점이 아니라 "같이 추리하는 사람"이다.
- **채팅 읽기 전용.** 훈수로 게임에 개입하는 것을 막는다.
- 라운드 결과 화면에서는 플레이어와 **동일한 정보**를 본다.
- UI에서 관전 상태를 분명히 드러낸다:
  - 상단 고정 배너 (`관전 중 — 다음 라운드부터 참여합니다`)
  - 참가자 목록과 **분리된 관전자 목록**
  - 채팅 입력창 비활성화 + 사유 안내
- **다음 라운드 시작 시 전원 자동으로 플레이어가 된다** (0점부터).
- 호스트는 관전자도 강퇴할 수 있다.

### F8. 연결 · 재접속 · 이탈

#### R1. 재접속 (30초 유예)
- 연결이 끊긴 플레이어는 **즉시 이탈로 처리하지 않는다.** 30초의 유예를 준다.
- 유예 내 재접속하면 **자리·역할·제시어·점수가 그대로 복구**된다.
- 새로고침, 네트워크 끊김, 앱 전환 후 복귀가 모두 여기에 해당한다.

#### R2. 유예 중 게임은 멈춘다
- 끊긴 플레이어가 있으면 **현재 단계의 타이머를 정지**한다.
  단계와 무관하게 일관되게 정지한다.
- 전원에게 `○○님 재접속 대기 중 (28초…)` 오버레이를 표시한다.
- **채팅은 계속 가능하다.** 멈춘 것은 게임이지 대화가 아니다.
- 호스트에게 **"기다리지 않고 계속"** 버튼을 제공한다 →
  누르면 즉시 유예를 끝내고 그 사람을 이탈 처리한다.
- **호스트 본인이 끊긴 경우**엔 30초 후 자동 진행 + 호스트 이양으로 자연 해소된다.

#### R3. 이탈 확정 시 처리

| 상황 | 결과 |
|---|---|
| **라이어 이탈 — 제시어 확인 중** | 라운드 **즉시 재시작** (새 라이어·새 단어, 점수 변동 없음, 라운드 수 미소모) |
| **라이어 이탈 — 설명 시작 후 ~ 피고 확정 전** | 라운드 **무효** (라이어·제시어만 공개, 점수 변동 없음, 라운드 수 미소모) |
| **라이어 이탈 — 피고 확정 후** | **시민 승 확정** (이미 잡혔으므로) |
| 시민 이탈 | 라운드 계속 (인원이 4명 이상인 한) |
| 플레이어가 4명 미만이 됨 | 라운드 무효 → 점수판 → 대기실 |
| 피고가 변론/투표 중 이탈 | 재토론 (기회가 남아 있으면), 소진 시 라이어 승 |
| 호스트 이탈 | 다음 참가자에게 호스트 이양 |
| 전원 이탈 | 짧은 유예 후 방 소멸 |

- 라이어 이탈을 **단계별로 차등**하는 이유(§8 D2): 일괄 "시민 승"은
  불리한 라이어가 나가서 정답 맞추기 역전 기회를 없애버리는 문제가 있고,
  일괄 "무효"는 반대로 라이어가 나가서 시민의 승리를 무효화할 수 있다.
  피고 확정을 경계로 나누면 양쪽 악용이 상쇄된다.

### F9. 연출

게임의 재미가 여기 상당 부분 걸려 있으므로 **부가가 아니라 기능**으로 취급한다.

| 연출 | 내용 | 타이밍 |
|---|---|---|
| 제시어 가리기 | 탭해야 자기 단어가 보임 (어깨너머 방지 + 긴장감) | — |
| 순서 추첨 | 하이라이트가 점점 느려지며 첫 설명자에서 멈춤 | 15~20회 순환, 시작 50ms에서 점증 |
| 한줄 설명 타이핑 | 제출된 설명이 한 글자씩 나타남 | 글자당 100ms, 총 3초 (여유는 대기) |
| 개표 카운트다운 | 찬반 공개 후 다음 단계까지 카운트다운 | 5초 |
| 라이어 공개 | `○○님은 라이어가…` 타이핑 → `맞습니다!` / `아닙니다!` | 1s → 0.5s 정지 → 1s → 1.5s 정지 |
| 지목 수 변동 | 득표가 늘어난 대상에 펄스 | 300ms |
| 타이머 경고 | 5초 이하에서 깜빡임 | — |

> 연출 시간을 서버 로직에 하드코딩하지 않는 방법은 `ARCHITECTURE.md`에서 다룬다.
> 여기서는 **연출의 존재와 길이만** 요구사항으로 고정한다.

### F10. 부가
- **인앱 피드백**: 3단 감정(😞😐😊) + 선택 메시지(최대 500자)를 운영자 채널로 전달.
  IP당 60초 쿨다운. 사용자가 "일주일간 숨기기" 가능.
  운영자 채널이 설정되지 않았거나 유효하지 않으면 기능 자체를 노출하지 않는다.
- 매치 종료 후 호스트가 **대기실로 되돌려** 새 매치를 시작할 수 있다 (멤버 유지).
- 검색엔진 대응: OG 태그, `sitemap.xml`, `robots.txt`.

## 7. 명시적 범위 밖 (Non-goals)

넣지 **않기로** 결정한 것들. 나중에 "이거 왜 없지?" 하지 않기 위해 기록한다.

- **계정 / 로그인 / 프로필** — 저마찰 진입이 핵심 가치다.
- **커스텀 단어 · 카테고리** — 하드코딩으로 충분 (D5).
- **음성 / 화상** — 텍스트 기반이 제품 정의다.
- **다국어 (i18n)** — 한국어 전용.
- **전역 랭킹 · 전적 저장** — 점수는 매치 내에서만 유효하다.
- **진행 중 게임의 영속화** — 서버 재시작 시 소실을 감수한다 (D9).
- **관전자 전용 채팅 채널** — 미니멀 원칙.
- **관전자 신 시점 옵션** — 정보 유출 위험이 이득보다 크다.
- **친구 초대 / 공유 링크 전용 UI** — 방 URL 자체가 초대 링크다.

| # | 결정 | 근거 |
|---|---|---|

| **D2** | 라이어 이탈을 **피고 확정 기준으로 차등** 처리 | 일괄 "시민 승"과 일괄 "무효"는 각각 반대 방향의 악용을 낳는다 (§F8 R3) |
| **D3** | 관전 허용, **공개 정보만**, 읽기 전용 채팅 | 관전자는 대개 플레이어의 지인이다. 제시어를 주면 유출로 게임이 죽는다 |
| **D4** | 연속 라운드 + 누적 점수 (라이어 +2 / 시민 +1 / 정확 지목 +1) | 라이어 승률이 50% 미만이므로 라이어 보상을 높인다. 지목 보너스로 "아무나 찍기" 억제 |
| **D5** | 커스텀 단어 없음 | 180단어 (카테고리당 30개)로 충분. 검열·중복 관리 비용 회피 |
| **D6** | 바보 모드 두 단어는 **완전 무작위** | 의미적 근접성 판정 로직을 넣을 가치가 없다 |
| **D7** | 최소 인원 **4명** | 3인이면 피고 제외 2명 → `찬성 > 1` 이라 **만장일치**가 요구되어 밸런스가 깨진다 |
| **D8** | 설명·토론 각 **2회** 상한, 소진 시 라이어 승 | 단일 원칙으로 세 갈래 예외를 통일. 라운드 종료가 보장된다 |
| **D9** | 진행 중 게임 영속화 안 함 | 재시작 빈도가 낮고, DB 도입 비용이 이득보다 크다 |
| **D10** | **라이어 선정은 완전 독립 시행** | 직전 라이어를 제외하면 그 사람이 "확정 시민"이 되어 정보가 샌다 |
| **D11** | 관전자 정원 = 최대 인원 − 플레이어 수 | `플레이어 + 관전자 ≤ 최대 인원` 불변식이 성립해 자동 승격이 정원을 넘지 않는다 |
| **D12** | 게임 중인 방도 로비에 노출 (`관전 가능` 배지) | 관전을 허용했으므로 진입 경로가 있어야 한다 |
